# Продолжить разработку на другом компьютере

## Что нужно поставить

| Что | Версия | Зачем |
|---|---|---|
| **Node.js** | 20 LTS или новее | всё остальное |
| **Git** | любая свежая | история правок |
| **VS Code** (или другой редактор) | — | писать код |
| **Claude Code** | — | если хотите продолжать так же |

Для мобильного клиента дополнительно:

| Что | Где | Зачем |
|---|---|---|
| **Xcode 26+** | только macOS | сборка iOS и Liquid Glass |
| **Android Studio** | любая ОС | сборка Android |

Собрать iOS-приложение можно **только на macOS** — это ограничение Apple, а не
проекта. Веб-часть разрабатывается на чём угодно.

## Что копировать

Архив собран скриптом ниже и весит несколько мегабайт. В него **не входят**:

- `node_modules` — 720 МБ, ставится одной командой;
- `frontend/.next` — 1 ГБ, это результат сборки, он пересоздаётся;
- то, что и так лежит в git.

## Что НЕ лежит в git и нужно перенести отдельно

Два файла с ключами. Они исключены из истории намеренно — секреты в
репозитории живут вечно, даже если их оттуда потом убрать.

```
backend/.env
frontend/.env.local
```

Если флешка может потеряться — не кладите их туда. Все значения берутся
заново в панели Supabase: **Project Settings → API**. Образцы полей лежат
рядом, в `backend/.env.example` и `frontend/.env.example`.

## Запуск на новом месте

```bash
cd frontend && npm install
cd ../backend && npm install
cd ../mobile && npm install
```

Дальше два окна терминала:

```bash
cd backend && npm run dev
```

```bash
cd frontend && npm run dev
```

Фронт поднимется на `localhost:3000`, бэкенд — на `localhost:4000`.

## Что ещё не выполнено в базе

Миграция `backend/migrations/009_message_replies_and_pins.sql` — ответы на
сообщения и закрепление. Выполнить целиком в Supabase → SQL Editor. До этого
переписка работает, но без цитат и закреплённых.

Проверить, какие миграции уже применялись, можно по наличию колонок: если в
`public.messages` есть `reply_to_id`, значит 009 прошла.

## Полезное

```bash
npm run build          # проверить, что всё собирается (в frontend)
npx tsc --noEmit       # проверить типы, ничего не собирая
npx eslint src --ext .ts,.tsx
```

Пять ошибок линта в `page.tsx`, `RollingNumber.tsx` и `i18n.ts` — давние и
известные, они не про свежие правки.

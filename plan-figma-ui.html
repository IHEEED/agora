Как спроектировать интерфейс соцсети с апвоутами в Figma — если вы никогда её не открывали

Продолжение плана: стек и архитектура уже выбраны, теперь очередь интерфейса. Здесь — пошаговая инструкция, как с нуля дойти до кликabельного макета всех экранов (лента, пост, профиль и остальные), который потом можно отдать в разработку.

01 / Фундамент

Зачем сначала Figma, а не сразу код

В общем плане проекта Фаза 0 уже отводила 1–2 недели на макет в Figma до первой строчки кода — вот детальная инструкция именно для этого этапа.

Пока экран существует только в коде, любое изменение — «подвинуть кнопку», «сделать карточку компактнее» — это правки в CSS/JSX и пересборка. В Figma то же самое — это перетаскивание мышкой за секунды, без единой строчки кода. Поэтому дешевле ошибиться и переделать макет 10 раз, чем один раз переделать готовый экран в React.

Второй эффект: у вас три «фасада» — сайт, iOS- и Android-приложение — которые показывают одни и те же посты, голоса и профили. Если сначала спроектировать переиспользуемые компоненты (карточка поста, кнопка голосования, аватар) в Figma, то и разработчик (тоже вы) переиспользует их логику в коде, а не изобретает вёрстку заново для каждого экрана.

02 / Старт

Первые шаги: аккаунт и интерфейс программы

Регистрация: зайдите на figma.com, зарегистрируйтесь бесплатно (почта или Google). Работает прямо в браузере, ничего устанавливать не обязательно — есть и десктопное приложение, но для старта хватит вкладки браузера.

Бесплатный тариф: личные черновики (Drafts) не ограничены по количеству — для одного человека, работающего вне команды, этого достаточно на весь проект. Единственное ограничение, которое встретится позже — режим Dev Mode для передачи разработчику недоступен на бесплатном тарифе; в разделе 15 показана бесплatная альтернатива.

Создание файла: на главном экране нажмите «+ Design file» — откроется пустой холст. Сразу переименуйте файл сверху слева, например «Соцсеть — UI».

Из чего состоит окно программы

  • Слева — панель Layers (список всех объектов на текущем экране, как папки и файлы) и вкладка Assets (ваши сохранённые компоненты)
  • Центр — холст (canvas), бесконечное полотно, на котором рядом друг с другом располагаются все экраны
  • Справа — панель Design (свойства выбранного объекта: размер, цвет, отступы) и вкладка Prototype (связи между экранами, раздел 14)
  • Сверху слева — тулбар: инструменты Move, Frame, фигуры, текст, комментарий
03 / Словарь

7 понятий Figma, без которых никуда

Дальше в плане эти слова используются постоянно — лучше один раз прочитать, что они значат, чем гадать по ходу дела.

01

Frame (фрейм)

Прямоугольная область фиксированного размера — это и есть «экран». Клавиша F, справа в панели можно выбрать готовый пресет размера, например «iPhone 14» или «Desktop».

Аналогия: лист бумаги, на котором рисуется один конкретный экран приложения.
02

Auto Layout

Превращает группу элементов в «резиновый» контейнер: сам расставляет отступы между элементами и растягивается при добавлении нового. Без этого при любой правке пришлось бы вручную двигать всё, что стоит ниже.

Аналогия: flexbox из CSS, только с визуальными ползунками вместо кода.
03

Component / Instance

Component — «эталон» элемента (например, карточка поста), Instance — его копия на экране. Меняете эталон один раз — меняются все копии сразу, во всех экранах, где они используются.

Аналогия: как переиспользуемый React-компонент — один источник правды для всех мест использования.
04

Variants

Разные состояния одного компонента, объединённые в один переключаемый набор: например, кнопка голосования — «обычная», «нажат апвоут», «нажат даунвоут».

Аналогия: пропс state у компонента, который меняет его вид.
05

Constraints

Правило, как элемент ведёт себя при изменении размера фрейма — «прилипнуть к левому краю», «растянуться по ширине». Важно для адаптации одного макета под разные экраны.

Аналогия: правила позиционирования, как position: sticky в вёрстке.
06

Styles (цвет / текст)

Именованный набор значений — например, цвет «Up / Orange» или текстовый стиль «Заголовок H2» — применяется в один клик вместо ручного подбора значений каждый раз.

Аналогия: CSS-переменные --up и классы типографики.
07

Prototype

Режим, в котором экраны соединяются стрелками-переходами: «нажатие на карточку поста → открывает экран поста». Результат — кликабельный макет, который можно открыть по ссылке как настоящее приложение.

Аналогия: роутинг между страницами, но без единой строчки кода.
04 / Решение

Дизайн-система: делаем один раз до любых экранов

Соблазн — сразу открыть фрейм и рисовать ленту. Правильный порядок — наоборот: сначала зафиксировать цвета, шрифты и отступы, чтобы потом не перекрашивать 40 элементов вручную.

Цвет: сохраните палитру как Color Styles

Up / Accent#ff4517
Down#4a5df0
Ink#1a1d23
Ink Soft#5a6070
Ink Faint#8a8f9c
Background#f6f6f3
  • Нарисуйте прямоугольник, залейте нужным цветом (панель Fill справа)
  • Кликните на кружок рядом с заливкой → значок «стиль» (четыре точки) → «+»
  • Назовите по смыслу, не по цвету: Up / Accent, а не «оранжевый» — при смене оттенка имя останется верным
  • Повторите для 6–8 базовых цветов: акцент, фон, поверхность, три оттенка текста, цвет ошибки/успеха

    • Шрифт: два семейства, не больше

    Space Grotesk + Inter

    • +Space Grotesk — для заголовков, у него характерный «инженерный» рисунок, хорошо читается крупным кеглем
    • +Inter — для основного текста, один из самых читаемых UI-шрифтов, бесплатный (Google Fonts)

    Системный шрифт (San Francisco / Roboto)

    • +Ничего подключать не нужно, выглядит «как родное приложение»
    • −Нет собственного характера, макет сложнее отличить от шаблонного
    ▲
    Рекомендация: та же пара шрифтов, что уже используется в текстовом плане проекта — согласованность визуального языка между документами и продуктом. Заведите 4–5 Text Styles: H1, H2, Body, Caption, Mono (для счётчиков голосов) — тем же способом, что и цвета.

    Сетка и отступы: система на 8

    Используйте отступы кратные 8 (8 / 16 / 24 / 32 / 48px) — глазу легче воспринимать регулярный ритм, а Auto Layout удобно настраивать круглыми числами. Радиус скругления карточек — 12–14px, той же логике, что в исходном стайлгайде плана (--radius: 14px).

    05 / Ключевой компонент

    Компонент №1: карточка поста

    Карточка поста встречается в ленте, в сообществе и в профиле — соберите её один раз как компонент, и дальше вставляйте копии.

    Из чего состоит карточка
    • Виджет голосования слева (компонент №2, раздел 06)
    • Аватар + название сообщества + автор + время («r/название · u/автор · 3ч»)
    • Заголовок поста
    • Превью картинки/видео (может отсутствовать — текстовый пост)
    • Нижняя строка: иконка комментариев + число, «Поделиться»
    Как собрать в Figma
  • Нарисуйте фрейм 400×140px (примерный размер одной карточки), внутри — прямоугольник-заглушка под будущий контент
  • Добавьте текстовые слои и виджет голосования, выставьте их мышкой примерно как на скетче
  • Выделите всё содержимое и нажмите Shift + A — включится Auto Layout, элементы встанут в ряд/колонку автоматически
  • В панели справа настройте направление (горизонтально), отступы между элементами (gap) и внутренние поля (padding) — кратно 8
  • Для заголовка поста задайте ширину Fill container, чтобы он растягивался и переносился на новую строку, а не вылезал за карточку
  • Выделите готовую карточку целиком → Ctrl/Cmd + Alt + K — превратится в Component (в Layers появится ромбик вместо квадрата)

    • Отсутствие картинки — тоже состояние, а не баг макета: в панели Assets создайте Variant карточки «без медиа», где блок превью просто скрыт (Boolean-свойство), а не оставляйте пустой серый прямоугольник, которого не будет в реальных данных.

    06 / Ключевой компонент

    Компонент №2: виджет голосования

    Самый маленький, но самый важный компонент продукта — с него стоит начать практику Variants.

    Три состояния (Variants)
    • Idle — обе стрелки серые, счёт нейтрального цвета
    • Upvoted — верхняя стрелка и счёт окрашены в акцентный оранжевый (--up)
    • Downvoted — нижняя стрелка и счёт окрашены в синий (--down)
    Как собрать
  • Соберите одно состояние (Idle): стрелка вверх, число, стрелка вниз — в вертикальной Auto Layout колонке, gap 2px
  • Сделайте Component (Ctrl/Cmd + Alt + K), затем скопируйте (Ctrl/Cmd + D) ещё 2 раза и перекрасьте копии в состояния Upvoted / Downvoted
  • Выделите все три копии → правая кнопка мыши → «Combine as variants» — Figma объединит их в один компонент с переключателем state
  • Вставьте этот компонент внутрь карточки поста из раздела 05 — теперь при обновлении виджета голосования он обновится сразу во всех карточках, где использован
    • 07 / Экран

    Лента

    Feed

    главный экран

    Список постов, отсортированных по одному из трёх режимов — то, что пользователь видит первым делом при открытии.

    Из чего состоит
    • Верхняя панель: логотип, иконка поиска, иконка уведомлений, аватар
    • Переключатель сортировки: Hot / New / Top (вкладки)
    • Список Instance-копий карточки поста (компонент из раздела 05), друг под другом
    • Нижняя навигация (мобильная версия): Главная / Поиск / Создать пост (+) / Уведомления / Профиль
    • Состояние загрузки следующей порции постов внизу списка
    Как собрать
  • Создайте фрейм под мобильный экран — при нажатии F справа выберите пресет телефона
  • Соберите верхнюю панель и нижнюю навигацию как отдельные компоненты — они переиспользуются почти на всех экранах
  • Между шапкой и навигацией — Auto Layout колонка с несколькими Instance карточки поста, gap 12px
  • Обязательно нарисуйте состояние «лента пуста» отдельным фреймом рядом — с иконкой и текстом «Пока нет постов — станьте первым» вместо пустого белого экрана
    • 08 / Экран

    Страница поста и комментарии

    Post Detail

    Открывается по нажатию на карточку в ленте — полный текст поста и дерево комментариев.

    Из чего состоит
    • Кнопка «назад» вверху
    • Полная карточка поста: заголовок, текст целиком, картинка/видео в полный размер, крупный виджет голосования
    • Переключатель сортировки комментариев: Лучшие / Новые
    • Поле ввода нового комментария (закреплено внизу экрана)
    • Список комментариев — у каждого свой мини-виджет голосования и отступ слева, растущий с глубиной вложенности (ответ на ответ)
    Как собрать
  • Дублируйте карточку поста, увеличьте ширину до полного экрана, растяните текстовый блок — компонент подстроится за счёт Fill container
  • Соберите один Component «Комментарий» с виджетом голосования, автором и текстом ответа
  • Для вложенных ответов не рисуйте отдельный компонент — оберните тот же компонент «Комментарий» во Frame с отступом слева 24/48/72px по уровню вложенности
  • Ограничьте глубину видимой вложенности 3–4 уровнями — глубже добавьте ссылку «Показать ещё ответы», иначе комментарии на телефоне превратятся в узкую полоску текста
    • 09 / Экран

    Профиль

    Profile

    Один макет экрана, два состояния: свой профиль и чужой — отличаются только правым верхним углом.

    Из чего состоит
    • Аватар, имя пользователя, карма (сумма голосов), короткое био
    • Своя страница: кнопка «Редактировать профиль»
    • Чужая страница: кнопка «Подписаться» / «Написать»
    • Вкладки: Посты / Комментарии / Сохранённое
    • Список карточек постов пользователя (тот же компонент из раздела 05)
    Как собрать
  • Соберите общую верхнюю часть (аватар, имя, карма, био) как один компонент с Variant-переключателем «own / other», меняющим только кнопку справа
  • Вкладки сделайте отдельным маленьким компонентом с состояниями active/inactive — переиспользуется и в сообществе (раздел 11)
  • Ниже — тот же список карточек постов, что и в ленте: не создавайте вторую версию карточки специально для профиля
    • 10 / Экран

    Создание поста

    Create Post

    Открывается по кнопке «+» в нижней навигации — форма публикации.

    Из чего состоит
    • Выбор сообщества (выпадающий список — «Выберите сообщество»)
    • Переключатель типа поста: Текст / Картинка / Ссылка
    • Поле заголовка (с ограничением по длине — покажите счётчик символов)
    • Поле текста или кнопка загрузки картинки, в зависимости от выбранного типа
    • Кнопка «Опубликовать», неактивна пока не заполнено обязательное поле
    Как собрать
  • Нарисуйте состояние кнопки «Опубликовать» в двух Variant: активная (акцентный цвет) и неактивная (серая, полупрозрачная) — это заранее покажет разработчику логику валидации формы
  • Три типа поста — это Variants одного фрейма формы, а не три разных экрана: переключается только средний блок под заголовком
    • 11 / Экран

    Сообщество

    Community

    Аналог сабреддита — лента, отфильтрованная по одному сообществу, плюс информация о нём.

    Из чего состоит
    • Баннер и иконка сообщества, название, число подписчиков
    • Кнопка «Подписаться» / «Отписаться»
    • Описание и краткие правила (сворачиваемый блок)
    • Та же лента постов, что и на главном экране, но только из этого сообщества
    Как собрать
  • Верхний блок (баннер + описание) соберите как отдельный компонент — переиспользуется, если позже понадобится страница «Создать сообщество» с похожей структурой
  • Ленту постов не пересобирайте — вставьте те же Instance карточки, что и в разделе 07
    • 12 / Остальное

    Остальные экраны — короче, но не менее важно

    Эти экраны реже попадают в первые наброски, но без них макет нельзя считать «полным комплектом», а не витриной из трёх красивых картинок.

    01

    Вход и регистрация

    Форма email + пароль, кнопки входа через Google/GitHub (переиспользуют кнопки из раздела 04 «Стили»), состояние ошибки под полем — «Неверный пароль», а не общее «Ошибка».

    02

    Поиск

    Поле ввода вверху, ниже — недавние запросы до начала ввода, после ввода — вкладки результатов: Посты / Сообщества / Люди.

    03

    Уведомления

    Список: «ответили в комментариях», «пост набрал 100 апвоутов» — сгруппируйте по дате (Сегодня / Ранее), непрочитанные выделите точкой акцентного цвета.

    04

    Настройки

    Аккаунт, уведомления (переключатели push/email), приватность, кнопка «Выйти» — отдельным, визуально «опасным» цветом от остальных пунктов.

    05

    Пустые состояния и ошибки

    Пустая лента, «нет интернета», «страница не найдена», «нет результатов поиска» — у каждого своя иконка и текст с понятным следующим шагом, а не просто «Ошибка».

    06

    Модерация

    Кнопка «Пожаловаться» на посте/комментарии с коротким списком причин, и отдельный экран очереди жалоб для модератора — даже если реализуете эту часть кода в последнюю очередь.

    13 / Решение

    Сайт и мобильное приложение: что переиспользовать

    У проекта три фасада — сайт, iOS и Android — но дизайнить с нуля три раза не нужно.

    Проблема: с какого размера экрана начинать

    Сначала мобильный фрейм (375×812)

    • +Мобильное приложение (React Native + Expo) — по общему плану проекта отдельная и полноценная часть продукта, а не «довесок» к сайту
    • +Уже спроектированные компоненты (карточка, виджет голосования) на узком экране проще растянуть на широкий, чем сжать широкий макет до телефона

    Сначала десктопный фрейм (1440×1024)

    • +Больше места, проще уместить все элементы на одном экране без прокрутки
    • −Легко «нарисовать» плотный десктопный интерфейс, который потом физически не влезает на телефон
    ▲
    Рекомендация: начните с мобильного фрейма 375×812 для всех 11 экранов выше. Когда компоненты и дизайн-система готовы, продублируйте 2–3 ключевых экрана (лента, пост) в десктопный фрейм 1440px — благодаря Auto Layout и Constraints большая часть содержимого просто перетечёт в более широкий контейнер без пересборки с нуля.

    Для десктопной версии используйте Constraints «Left and Right» на центральной колонке ленты, чтобы она не растягивалась на всю ширину монитора, а оставалась читаемой шириной (около 600–680px) с пустыми полями по бокам — так же, как в этом текстовом плане.

    14 / Практика

    Прототип: делаем макет кликабельным

    Пока экраны не связаны друг с другом — это просто картинки. Режим Prototype соединяет их в интерактивный макет.

    01

    Переключитесь на вкладку Prototype

    Справа, там же где была вкладка Design — переключатель вверху правой панели.

    02

    Наведите на карточку поста в ленте

    Справа от неё появится синий кружок — потяните из него стрелку к фрейму экрана поста. Это и есть переход «On tap → Navigate to».

    03

    Повторите для всех переходов

    Кнопка «+» → экран создания поста, аватар → профиль, иконка сообщества → экран сообщества, нижняя навигация → соответствующие экраны.

    04

    Добавьте отклик на голосование

    Для виджета голосования свяжите переход не между экранами, а между Variants компонента («Idle → Upvoted» при нажатии) с анимацией Smart Animate — кнопка визуально «оживёт» без единой строчки кода.

    05

    Нажмите ▶ Present

    Откроется отдельное окно, где по макету можно кликать как по настоящему приложению — это удобно проверять на себе и показывать другим людям для обратной связи.

    15 / Передача

    Передача в разработку

    Раз кодить сайт и приложение тоже будете вы — этот раздел скорее «шпаргалка самому себе», чем инструкция для чужого разработчика.

    Важный нюанс бесплатного тарифа: полноценный режим Dev Mode (с автогенерацией CSS/значений в один клик) на бесплатном тарифе Figma недоступен. Это не блокирует работу — нужные значения всё равно доступны через обычную панель Design и контекстное меню, просто на один клик больше.

    01

    Считать отступы и размеры

    Выделите элемент — в панели Design справа видны точные значения width/height/padding/gap в пикселях, их и переносите в CSS/Tailwind-классы.

    02

    Скопировать цвет

    Клик по кружку заливки → значение HEX копируется напрямую, вставляется в CSS-переменную.

    03

    Экспорт иконок

    Выделите иконку → внизу панели Design «Export» → формат SVG — векторная иконка не теряет чёткость на любом экране, в отличие от PNG.

    04

    Поделиться ссылкой

    Кнопка «Share» вверху справа → «Anyone with the link can view» — по этой ссылке макет открывается в браузере без аккаунта Figma, удобно смотреть с телефона во время вёрстки.

    16 / Порядок действий

    Поэтапный план работы в Figma

    Шаг 1 — Дизайн-система

    1–2 дня

    Color Styles, Text Styles, отступы кратные 8. Разделы 04.

    Шаг 2 — Базовые компоненты

    2–3 дня

    Карточка поста, виджет голосования, кнопка, верхняя панель, нижняя навигация. Разделы 05–06.

    Шаг 3 — Основные экраны

    3–5 дней

    Лента, пост с комментариями, профиль, создание поста, сообщество — из уже готовых компонентов. Разделы 07–11.

    Шаг 4 — Второстепенные экраны

    2–3 дня

    Вход/регистрация, поиск, уведомления, настройки, пустые состояния и ошибки. Раздел 12.

    Шаг 5 — Прототип

    1 день

    Соединить все экраны переходами, добавить отклик кнопки голосования. Раздел 14.

    Шаг 6 — Обратная связь

    1–2 дня

    Показать кликabельный макет 2–3 людям со стороны, спросить: «Что непонятно с первого взгляда?» — и поправить до начала кода, а не после.
